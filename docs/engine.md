# 引擎设计

> 这份文档记录的是**为什么**这样做，不是怎么用。用法看 README。

## 三个基本判断

### 1. 瓶颈是判断力，不是产出速度

调度器、队列、重试、并发——这些几天就能写完，不是护城河。

真正难的是：**模型能写出「还不错的一章」，但写不出「三十万字之后仍然成立的一本书」。** 角色口吻漂移、伏笔埋了不回收、设定前后矛盾、中段节奏塌方——这些是叙事学问题。

所以引擎的算力预算里，**写只占 1/3，剩下 2/3 全部花在「判断这一章行不行」上。**

### 2. 读者反馈是滞后信号

「质量由读者反馈决定」是对的，但读者是**用弃书投票**的。等他投完票，你已经写完 15 章了。

所以必须分层：

| 层 | 信号 | 延迟 | 作用 |
|---|---|---|---|
| 冷读预测 | 机器模拟读者：会不会点下一章 | 秒 | 每章放行前拦截 |
| 内部批评 | 五个专职批评家 | 分钟 | 定点修缮 |
| 真实读者 | 追读率、弃书点、评论 | 天 | 唯一有资格定义「好」 |

前两层不是为了替代第三层，是为了**给第三层争取时间**。

冷启动期没有读者，第三层是空的。这时候你和内部批评家顶替它——但引擎必须写成「信号可插拔」的样子，等有人读的时候能直接接上。

### 3. 中文网文是可工程化的

纯文学没法工程化，它的好是「无法预判的意外」。

但网文有成熟的工业标准：黄金三章、每章 2000–3000 字、章末必留钩子、三章一小高潮、十章一中高潮。这些节拍本来就是表格。

**我们挑战的不是文学创作，是一条有明确合格线的类型小说生产线。**

## 一个夜晚的时刻表

现在还是手动触发，这是它最终该有的样子：

```
02:00  全书重读审计
       把已写的全部章节重读一遍，只输出「漂移报告」：
       口吻变形 / 设定冲突 / 事实矛盾 / 逾期未还的债 / 重复桥段
       —— 这是人类编辑最费神、也最有价值的一件事

02:20  规划       把大纲拆成场景，每个场景必须有转折
02:50  开场 ×4    不同切入方式，由一个挑剔编辑选出最好的
03:30  起草       + 五个批评家并行开火
04:30  定点修订   只改被点名的句子
05:30  终审       不过线打回，最多三轮
07:00  发布
```

五小时机器时间换一章。这不是浪费——**时间是唯一可以买品质的东西。**

## 判据（gate）

一章要放行，三条同时满足：

1. 没有 `blocker` 级缺陷
2. 五个批评家的平均分 ≥ 7.5
3. 三个冷读分身里至少两个说「会点下一章」

不满足就修订，最多三轮。最后用**分数最高的那一版**，而不是最后一版——修订有时会改坏。

## 两个防作弊机制

### 批评家必须逐字引用

`critics.ts` 里的 `verifyQuotes()` 会检查每条缺陷的 `quote` 是否真的出现在正文里。引用不到的，直接作废并计数。

不加这一条，模型会写出一堆「人物略显单薄」这种既对又没用的话，然后你花三次调用去修一个不存在的问题。

### 写手和批评家必须不同源

同一个模型审自己的稿，盲区完全重合——它会真诚地认为自己的平庸句子很好。

`npm run doctor` 会检查这一点。目前只配了 DeepSeek 一家，所以是「同族但不同模型」（chat 写、reasoner 审），这是**打折的**多样性。配第二个厂商（Kimi / GLM / 通义）质量会有可感知的提升。

## 故事圣经为什么是文件而不是数据库

创作侧用文件，阅读侧用数据库。

- 圣经是**人也要读要改**的东西，Markdown / JSON 能用 git 看 diff，能在编辑器里直接改
- 事实和伏笔是引擎读写的，用 JSONL 追加，可回溯
- 等有了读者，章节、评论、埋点才需要数据库

把创作产物放进数据库的唯一后果是：你不敢改，也看不懂。

## 算力要偏心地分配

一本书的生死在前三章。第 1 章留不住人，后面写得多好都没人知道。

引擎必须允许**不对称预算**：
- 第 1–3 章：开场候选 ×8，修订轮数 ×3，反复冷读
- 第 4 章之后：标准档

已实现（`profileFor`）：第 1–3 章开场候选 ×8、修订 3 轮、要求冷读 3/3 全票；第 4 章起降到 ×4 / 2 轮 / 2 票。

另外 `--candidates K` 可以让同一章跑 K 个变体（温度 0.90 / 0.95 / 1.00 …），比完再落盘。第一章值得这么干。

## 调参实录（2026-10，第一章，¥9 换来的）

这些是实测结论，不是推测。改引擎之前先读一遍。

### 1. `reasoning_effort` 会反向咬人

想压低批评家的思考量，加 `reasoning_effort: "low"`——结果推理量从 0 涨到 8k–23k 字，
耗时从 6 秒涨到 28 秒，内容还是被截断的空字符串。

对照实验（同一份真实审稿 prompt）：

| 配置 | 耗时 | 输出 token | 推理字数 | 结果 |
|---|---|---|---|---|
| reasoner + low | 32s | 5000（截断） | 16342 | JSON 坏 |
| chat + low | 28s | 5000（截断） | 7832 | JSON 坏 |
| **chat + 不传该参数** | **6s** | **789** | **0** | **JSON 好** |
| reasoner + 不传 | 36s | 5923 | 16333 | JSON 好 |

结论：**不要传 `reasoning_effort`**。`deepseek-reasoner` 永远推理，`deepseek-chat` 不传该参数时零推理。
现在只有 planner / auditor 用 reasoner，其余全部 chat。

### 2. 缺陷条数不能当闸门

五个批评家，每个写 5–6 条意见，一章就是 30 条。曾经用「均分 ≥7.5」「blocker ≥1 就拦」，
结果**没有任何一章能过**，而且每轮修订都在增加 blocker（5→3→1→2→4 震荡）。

批评家是被要求挑刺的，6 分意味着「合格但有毛病」。现在闸门是：

- 冷读票数达标（这是唯一和「读者愿不愿意翻页」直接挂钩的指标）
- 最低分 > 3
- 打 4 分以下的不超过 1 位
- blocker ≥ 5 才拦

### 3. 修订的边际收益是负的

整章重写修订：每修一处带进三处新错，均分 6.6 → 6.4 → 5.8。
改成补丁式（模型只输出「原文片段 → 改文片段」，引擎机械替换，找不到就跳过）后不再伤及无辜，
但**评分仍然在降**（6 → 5.7 → 5）。

所以：黄金三章改为「独立多跑几版再挑」（`--candidates 3`），修订只留一轮兜底，
并且一旦发现修订后变差就回退。

### 4. 批评家会按写实标准杀死超自然设定

第一章的核心钩子是「十七年前的陈血还是湿的」。三个批评家连续两轮把它当物理错误要求修改。

补丁：在 `premise.md` 里写一节「允许的异常」，并让**所有**批评家都读到前提
（之前只有连续性编辑能看设定）。判断标准改成「主角有没有察觉到不对劲」——
察觉到了就成立，毫无反应才是 bug。

## 已知的坑

1. **自己评自己**：批评家和写手同厂商，相关性太高。缓解：异厂商、不同 rubric、要求引用原文。
2. **修订跑偏**：模型修 A 的时候顺手把 B 也改了。缓解：明确「没被点名的地方一个字都不要动」，并且保留最高分版本。
3. **冷读分身说客套话**：三个分身都是同一个模型，可能都高估。缓解：人格差异要做足（老书虫 / 通勤读者 / 解谜读者的判断标准确实不同）。
4. **长程一致性靠不住**：等到 20 章以后，靠摘要 + 事实表可能不够。那时候要上向量检索或分级摘要。
5. **「AI 写的」是减分项**：读者不在乎谁写的，只在乎好不好看。所以对外不需要强调引擎，只需要强调故事。

## 第一章实测成绩（2026-10-23）

| 指标 | 结果 |
|---|---|
| 耗时 | 2 分 10 秒（8 个开场候选 → 起草 → 5 批评家 → 3 冷读 → 放行） |
| 成本 | ¥0.31 |
| 字数 | 2135 |
| 冷读 | 3/3 说会点下一章 |
| 批评家均分 | 6.4（最低 6） |
| 修订轮次 | 0（第一轮就过线） |

批评家提出的有效问题（供下一轮改 prompt 用）：
- 主角直接用手刮血痂，缺乏「能不能碰」的犹豫，与他的谨慎不一致
- 老周说出「那册书是我爹抄的」——违反「禁言」设定，他不能直白陈述
- 「气感」「引气」这类词不该出现在抄书匠的叙述里

## 第二轮踩到的坑（前三章）

### 1. 派生数据必须按章幂等

重跑一章时，正文被覆盖了，但 `facts.jsonl` 是追加写的、`promises.json` 只增不减。

结果：三次重跑之后，事实表里同时存在
「老周这是第四回」「老周十七岁也在藏经阁扫地」「老周只见过一次献祭」三种互相矛盾的说法，
伏笔账本从 10 条涨到 22 条。这些垃圾会作为上下文喂给后面每一章。

修法：
- `replaceFacts(slug, n, facts)`：按章替换，不是追加
- 自动生成的伏笔用 `g{章}-{序}` 前缀，重跑时按前缀清掉，手写的 p1–p10 不动
- `npm run recanon -- --n 3`：从定稿正文重算某章的派生数据

### 2. 连续性批评家只看摘要是不够的

第三章把「《引气篇》放在不上锁的木函里」（第一章原文）改成了「藏在架子和墙的缝隙里」。
连续性批评家没发现——因为它只拿到摘要和事实表，看不到第一章原文。

修法：连续性和逻辑批评家额外拿到**前两章的原文**（约 4k token，成本可接受）。

### 3. 大纲自身会和生产出来的正文打架

第二章的章末钩子是我写的「你翻错了书。不是那本」，但第一章里主角翻的确实就是《引气篇》。
写手忠实地照着写，于是产出一个和已发表章节冲突的反转。

教训：**大纲的每一条都要能被已写章节验证**，否则写手只能二选一——违背大纲，或违背正文。

### 4. 确定性检查比模型检查便宜得多

禁用词、失声词、超长句、情绪直陈——这些可以机械判定。
新增 `lint.ts` 在起草后立刻跑一遍，第三章命中 9 处、第二章 11 处，
一次定点清洗调用（¥0.03）全部修好，不需要五个批评家去发现。

顺序应该是：**能 grep 的别问模型，能问模型的别问人。**

## 第三轮的坑（第 4–5 章）

### 1. `response_format: json_object` 要求提示词里出现 "json"

全书审计一直 400，返回体还是空的，查了很久。原因是 DeepSeek 的 JSON 模式要求提示词里
必须字面出现 "json" 这个词，而审计的提示词只写了个 JSON 结构示例，没说这个词。

所有要求 JSON 的提示词现在都必须包含「只输出 JSON」。

另外：`res.text()` 为空时要回落到 `statusText`，否则日志里只剩一行「HTTP 400：」什么线索都没有。

### 2. 字数系统性少 20%

整章只给一个总目标（2600 字），模型写出来稳定在 2000–2100。
改成**按场景分配配额**（三场 × 850 字），并在提示里逐场景标注配额后，稳定到 2400–2800。

补写阈值也从 0.7 提到 0.9。

### 3. 伏笔账本会永远红着

规划阶段按大纲写，不会主动去还那些大纲里没有的债。账本于是积累逾期项，越积越多。

修法：plan 增加 `defer` 字段。规划时对每一条逾期/临近到期的债必须三选一：
本章还掉 / 本章点一下并推迟 / 明确延期并给新期限。引擎按 `defer` 更新账本。

### 4. 每章用同一招收尾

五章里有四章以「认出笔迹 / 认出了那个钩」收尾。这种问题单个批评家看不出来——它只读一章。

修法：起草时把**最近三章的结尾原文**放进提示词，明确要求换一种收法。
这类「只有通读全书才能发现」的问题，正好是 nightly audit 该干的活。

### 5. 人工批注通道

`npm run fix -- --n 2 --m "老周不该讲解规则"` —— 走补丁式修订，改完自动提示 recanon。

有了它，"编辑说一句、机器改一处" 就是可复现的操作，而不是某个人记得自己手改过。

## 判据本身要能证伪

一个从来不说「不」的测试，测不出任何东西。

前五章整章冷读全是 3/3、首屏也全是 3/3。这个结果有两种解释：
一是书写得真好，二是这套判据根本没有分辨力。必须排除第二种。

### 做法：喂一段故意写烂的稿子

`fixtures/bad-chapter.md` 是一段标准套话堆出来的网文：
「月色如水」「心中一凛」「深不可测的气息」「瞳孔骤缩」「嘴角勾起」「惊涛骇浪」，
没有一件具体的事发生。

`npm run calibrate` 同时跑烂稿和第一章：

```
烂稿　     0/3 会继续
第一章　   3/3 会继续
烂稿首屏　 0/3 会继续滑
第一章首屏 3/3 会继续滑
判别力 足够（整章 3，首屏 3）
```

三个分身对烂稿的诊断都很准（「没有一件具体的事发生」「全靠拖」），
说明它们真的在读，不是在点头。

### 为什么要把它固化成命令

模型会升级。哪天换了模型，读者分身可能变得「什么都夸」——
这时候 `npm run calibrate` 会红，而不是让你在三个月后才发现所有章节都过了。

### 两个测试测的不是一回事

- **整章冷读**：读完之后，想不想看下一章
- **首屏测试**：只看开头 320 字，会不会继续往下滑

手机读者看不到「整章好不好」，他在前两屏就走了。两个都得过。

### 读者必须对作者的意图盲

早期版本会把《文风规范》塞给冷读分身。那是错的：读者不知道、也不关心作者想追求什么，
塞给他只会让他去检查合规，而不是回答「我想不想翻页」。

现在读者只拿到「前情提要 + 这一章」——就像真实读者一样。
移除文风规范之后，五章仍然全是 3/3，说明那个信号不是喂出来的。
